Two things to notice, because both cause errors constantly:

The colon. if temperature < 10: ends with :. Leave it out and you get a SyntaxError.

The indentation. The print lines are indented by four spaces. In Python, indentation is not decoration — it is how the language knows which lines belong to which block. Everything indented under the if runs when the condition is true. Get it wrong and the program does something different, or refuses to run.

Repeating until something is true

This is the important one.

Output: 3, 2, 1, Go.

Read while count > 0: as "as long as count is greater than zero, keep doing the indented part". Before each repetition Python re-checks the condition. When it becomes false, the loop ends and the program carries on below.

The line count = count - 1 looks strange if you read = as "equals" — it is not a mathematical claim, it is "take the current value of count, subtract one, and store the result back under count". Without it, count would stay at 3 forever and the loop would never end.

Infinite loops

If the condition never becomes false, the loop runs forever and your program hangs.

Press Ctrl + C in the terminal to stop a runaway program. Learn that now; you will need it.

Remember this feeling. In Module 1 you will discover that an AI agent is a while loop, that agents absolutely can fail to stop, and that Ctrl + C is not available when it is running on a server spending real money. Everything Module 1 says about turn caps and budget caps is this problem, grown up.

Holding labelled information: dictionaries

A list holds things in order. A dictionary holds things by label.

The label is called a key; the thing it points at is the value. You look things up by key rather than by position, which is far easier to read than remembering that position 2 was the age.

Functions: naming a piece of work

A function is a chunk of instructions with a name, so you can use it repeatedly without writing it out again.

  • def starts a definition. greet is the name you chose.
  • name in the brackets is the parameter — information handed in when the function is used.
  • return sends a result back out.
  • The indented lines are the body. They do not run when you define it; they run when you call it.

Defining is not calling. def greet(name): creates the function. greet("Ada") runs it. A function you define and never call does nothing at all — a genuinely common source of "why is nothing happening".

Why bother with functions at all

Three reasons, and they compound.

You write it once. Change the greeting in one place rather than in forty.

You can name the idea. calculate_cost_of_turn(...) says what is happening. Ten lines of arithmetic in the middle of a loop does not.

You can test it in isolation. Later in the course, every ship gate is a test that calls one function with known inputs and checks what comes back. That is only possible because the work lives in a function with a clear way in and a clear way out.

When you read the agent in Module 1, notice that the tool-executing part is its own function. That is not an accident — it is what lets you check it separately from the loop around it.

str() and round()

str(0.0069) turns a number into text, so it can be joined onto other text with +. Without it you get TypeError: can only concatenate str to str — a very common early error.

round(0.006933, 5) shortens a decimal to five places.

What you now know

  • if / else chooses a path. The colon and the indentation are both load-bearing.
  • == compares; = stores.
  • for goes through a collection; while repeats until a condition goes false.
  • An infinite loop is a real failure mode. Ctrl + C stops one.
  • Lists hold things in order (counting from 0); dictionaries hold things by key.
  • Functions name a piece of work, take inputs, and return results.
