What we are doing and why

A program is a list of instructions written in a file. You run the file, and the computer follows the instructions in order. That is the whole idea.

By the end of this module you will have written one and watched it run. It will be small. That is fine — the agent you build in Module 1 is about sixty lines, and every one of them is made of the things you are about to learn.

We use Python, because it reads more like English than most languages and because the tools for working with AI models are built for it.

Terminal

A window where you type commands instead of clicking things. Also called the command line, the shell, the console, or the prompt. Same thing.

It looks intimidating and is not. It does exactly one job: you type an instruction, press Enter, and it does the thing.

Step 1 — open a terminal

Mac: Press ⌘ + Space, type Terminal, press Enter.

Windows: Press the Start button, type PowerShell, press Enter.

Linux: Ctrl + Alt + T usually does it.

If nothing happened

Check you pressed Enter, and that you typed echo hello and not echo "hello with a stray quote. The terminal is picky about exact characters and completely unforgiving about typos — that is normal and you will get used to it faster than you expect.

Step 2 — install Python

First check whether you already have it. Type:

If you see something like Python 3.11.5, you have it — skip to step 3. Any version starting with 3.10 or higher is fine.

If you see an error, install it:

  • Mac and Windows: go to python.org/downloads, download the installer, run it. On Windows, tick the box that says "Add Python to PATH" on the first screen — it is easy to miss and everything breaks without it.
  • Linux: sudo apt install python3 on Ubuntu or Debian.

Close the terminal, open a new one, and run python3 --version again. It should work now.

PATH

A list your computer keeps of places to look for programs. When you type python3, your computer searches that list to find it.

"Add Python to PATH" means "put Python somewhere I will look". If you skipped that box on Windows, the fix is to re-run the installer and tick it.

print()

An instruction that displays something on screen. print("hello") shows hello.

The round brackets hold what you want printed. The quote marks say "this is text, not an instruction". Both matter, and leaving one out is the most common beginner error there is.

The kinds of information you will use

Python distinguishes between a few types of thing, and mixing them up causes a lot of early errors:

TypeWhat it isExamples
stringText. Always in quote marks."hello", "Ada", "42"
integerA whole number. No quotes.42, 0, -7
floatA number with a decimal point.3.14, 0.5
booleanTrue or false. Capital letter, no quotes.True, False

The one that catches everyone: "42" and 42 are different things. The first is text that happens to look like a number; the second is a number you can do arithmetic with.

Neither is wrong. They are different operations, and Python did exactly what you asked.

Comment

Anything after a # is ignored by the computer. It is a note for humans reading the code.

Good code is full of them. You will thank yourself in a month.

Step 5 — reading errors

You will see errors constantly. Everyone does, at every level of experience. An error is not you failing — it is the computer telling you precisely what confused it, which is enormously more useful than it silently doing the wrong thing.

Errors are read bottom-up. The last line is what went wrong; the lines above say where.

Here are the three you will actually hit this week.

SyntaxError

Means: you broke a rule of the language — usually a missing quote mark or bracket. Look at: the line number given, and the one before it. Count your quotes and brackets.

NameError

Means: you used a name Python has never seen. Almost always a typo, or using a variable before creating it. Look at: the spelling. nmae versus name.

FileNotFoundError, or "can't open file"

Means: you are not in the folder where your file lives. Fix: run ls (Mac/Linux) or dir (Windows) to see what is in the current folder. If hello.py is not listed, cd into the right folder.

The most valuable habit you can build today

When you hit an error, read it. Actually read it. The instinct is to feel a flash of alarm and start randomly changing things — everyone has it, and it costs hours.

The error usually tells you the file, the line, and the problem. Nine times in ten the fix is sitting in the message.

What "python3" is actually doing

When you type python3 hello.py, you are running a program called python3 and handing it your file. It reads your file top to bottom and carries out each instruction in order.

Python is an interpreted language: it reads and executes as it goes, rather than being converted into machine instructions ahead of time. That is why you see errors when execution reaches the bad line, rather than before anything runs at all.

You do not need this to continue. It is here because "what is actually happening when I press Enter" is a reasonable question, and the answer is not mysterious.

What you now know

  • A terminal takes typed commands. mkdir, cd, ls/dir, python3.
  • A program is instructions in a file, run top to bottom.
  • print() displays things.
  • A variable is a name for a piece of information; = means "put this under this name".
  • Text, whole numbers, decimals and true/false are different types, and "42" is not 42.
  • Errors are read bottom-up and usually tell you the fix.
