## Four ideas

Everything a program does is built from a handful of ideas. You met one already — storing
information in a variable. Here are the rest, and then you have enough to read the agent in Module 1.

The last one on this page is not a metaphor. The `while` loop you write in ten minutes is
structurally the same as the agent loop you build in Module 1. That is why this module exists.

## Making a decision: if

```python title=weather.py
temperature = 4

if temperature < 10:
    print("Wear a coat.")
else:
    print("You'll be fine.")
```

Run it: `Wear a coat.` Change `4` to `20`, run it again: `You'll be fine.`

Two things to notice, because both cause errors constantly:

**The colon.** `if temperature < 10:` ends with `:`. Leave it out and you get a SyntaxError.

**The indentation.** The `print` lines are indented by four spaces. In Python, **indentation is not
decoration — it is how the language knows which lines belong to which block.** Everything indented
under the `if` runs when the condition is true. Get it wrong and the program does something
different, or refuses to run.

```python
if temperature < 10:
print("Wear a coat.")        # IndentationError — Python cannot tell this belongs to the if
```

### Comparisons

| You write | It means |
|---|---|
| `a == b` | a is equal to b |
| `a != b` | a is not equal to b |
| `a < b` | a is less than b |
| `a >= b` | a is greater than or equal to b |
| `a in b` | a appears inside b |

The one that bites everyone: **`=` stores a value, `==` compares two values.** `x = 5` puts 5 into
x. `x == 5` asks whether x is 5, and answers `True` or `False`.

You can check more than one thing at once with `and` and `or`, and flip a check with `not`:

```python
if temperature < 10 and raining:
    print("Coat and umbrella.")
```

## Repeating: loops

### Going through a list of things

```python title=cities.py
cities = ["Oslo", "Lisbon", "Cairo"]

for city in cities:
    print("Checking the weather in " + city)
```

Output:

```
Checking the weather in Oslo
Checking the weather in Lisbon
Checking the weather in Cairo
```

Read `for city in cities:` as *"take each thing in `cities`, call it `city`, and do the indented
part"*. The name `city` is yours to choose — it just holds one item at a time.

::: jargon List
An ordered collection, written in square brackets: `["Oslo", "Lisbon", "Cairo"]`.

Lists can hold anything, and can grow:

```python
cities = []                   # start empty
cities.append("Oslo")         # add to the end
print(len(cities))            # 1 — len() gives the number of items
print(cities[0])              # Oslo — position 0 is the FIRST item
```

Counting from zero is normal in programming and feels wrong for about a week.
:::

### Repeating until something is true

This is the important one.

```python title=countdown.py
count = 3

while count > 0:
    print(count)
    count = count - 1

print("Go.")
```

Output: `3`, `2`, `1`, `Go.`

Read `while count > 0:` as *"as long as `count` is greater than zero, keep doing the indented
part"*. Before each repetition Python re-checks the condition. When it becomes false, the loop ends
and the program carries on below.

The line `count = count - 1` looks strange if you read `=` as "equals" — it is not a mathematical
claim, it is "take the current value of count, subtract one, and store the result back under
`count`". Without it, `count` would stay at 3 forever and the loop would never end.

::: warn Infinite loops
If the condition never becomes false, the loop runs forever and your program hangs.

```python
count = 3
while count > 0:
    print(count)          # nothing ever changes count — this never stops
```

**Press Ctrl + C in the terminal to stop a runaway program.** Learn that now; you will need it.

Remember this feeling. In Module 1 you will discover that an AI agent is a `while` loop, that agents
absolutely can fail to stop, and that Ctrl + C is not available when it is running on a server
spending real money. Everything Module 1 says about turn caps and budget caps is this problem,
grown up.
:::

## Holding labelled information: dictionaries

A list holds things in order. A **dictionary** holds things by label.

```python title=person.py
person = {
    "name": "Ada",
    "city": "London",
    "age": 36,
}

print(person["name"])        # Ada
print(person["age"])         # 36
```

The label is called a **key**; the thing it points at is the **value**. You look things up by key
rather than by position, which is far easier to read than remembering that position 2 was the age.

```python
person["job"] = "engineer"        # add a new pair
print(len(person))                # 4
print("city" in person)           # True — is there a key called city?
```

Dictionaries matter enormously for the rest of this course, because **this is the shape of the
messages you send to Claude.** In Module F4 you will write exactly this:

```python
{"role": "user", "content": "What's the weather in Oslo?"}
```

A dictionary with two keys. You already understand it.

::: jargon Nesting
Lists and dictionaries can hold each other, to any depth. This looks alarming and is just the two
ideas combined:

```python
conversation = [
    {"role": "user", "content": "Hello"},
    {"role": "assistant", "content": "Hi there"},
]

print(conversation[0]["content"])     # Hello
```

Read it left to right: take `conversation`, take item `0` (the first), take the value under
`content`. That is the entire trick, and that structure is the conversation you send to Claude on
every single call.
:::

## Functions: naming a piece of work

A function is a chunk of instructions with a name, so you can use it repeatedly without writing it
out again.

```python title=greet.py
def greet(name):
    message = "Hello, " + name + "."
    return message

print(greet("Ada"))          # Hello, Ada.
print(greet("Grace"))        # Hello, Grace.
```

- `def` starts a definition. `greet` is the name you chose.
- `name` in the brackets is the **parameter** — information handed in when the function is used.
- `return` sends a result back out.
- The indented lines are the body. They do not run when you define it; they run when you *call* it.

**Defining is not calling.** `def greet(name):` creates the function. `greet("Ada")` runs it. A
function you define and never call does nothing at all — a genuinely common source of "why is
nothing happening".

A function can take several parameters, and can have defaults:

```python
def describe(city, country="unknown"):
    return city + " is in " + country

print(describe("Oslo", "Norway"))    # Oslo is in Norway
print(describe("Atlantis"))          # Atlantis is in unknown
```

::: deeper Why bother with functions at all
Three reasons, and they compound.

**You write it once.** Change the greeting in one place rather than in forty.

**You can name the idea.** `calculate_cost_of_turn(...)` says what is happening. Ten lines of
arithmetic in the middle of a loop does not.

**You can test it in isolation.** Later in the course, every ship gate is a test that calls one
function with known inputs and checks what comes back. That is only possible because the work lives
in a function with a clear way in and a clear way out.

When you read the agent in Module 1, notice that the tool-executing part is its own function. That
is not an accident — it is what lets you check it separately from the loop around it.
:::

## Putting it together

This program has every idea on the page, and is a recognisable skeleton of what you build next
module:

```python title=budget.py
def cost_of(tokens, price_per_thousand):
    """Work out what a number of tokens costs."""
    return (tokens / 1000) * price_per_thousand


calls = [
    {"name": "first question", "tokens": 620},
    {"name": "follow-up", "tokens": 1450},
    {"name": "final answer", "tokens": 2300},
]

total = 0.0
budget = 0.01

for call in calls:
    price = cost_of(call["tokens"], 0.003)
    total = total + price
    print(call["name"] + " cost " + str(round(price, 5)))

    if total > budget:
        print("Stopping: over budget.")
        break

print("Total: " + str(round(total, 5)))
```

Everything in there is something you now know: a function with a return value, a list of
dictionaries, a loop over that list, a lookup by key, an if that checks a condition, and `break` to
leave a loop early.

::: jargon str() and round()
`str(0.0069)` turns a number into text, so it can be joined onto other text with `+`. Without it you
get `TypeError: can only concatenate str to str` — a very common early error.

`round(0.006933, 5)` shortens a decimal to five places.
:::

## What you now know

- **`if` / `else`** chooses a path. The colon and the indentation are both load-bearing.
- **`==` compares; `=` stores.**
- **`for`** goes through a collection; **`while`** repeats until a condition goes false.
- An infinite loop is a real failure mode. Ctrl + C stops one.
- **Lists** hold things in order (counting from 0); **dictionaries** hold things by key.
- **Functions** name a piece of work, take inputs, and return results.
