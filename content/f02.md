## What we are doing and why

A program is a list of instructions written in a file. You run the file, and the computer follows
the instructions in order. That is the whole idea.

By the end of this module you will have written one and watched it run. It will be small. That is
fine — the agent you build in Module 1 is about sixty lines, and every one of them is made of the
things you are about to learn.

We use **Python**, because it reads more like English than most languages and because the tools for
working with AI models are built for it.

::: jargon Terminal
A window where you type commands instead of clicking things. Also called the command line, the
shell, the console, or the prompt. Same thing.

It looks intimidating and is not. It does exactly one job: you type an instruction, press Enter, and
it does the thing.
:::

## Step 1 — open a terminal

**Mac:** Press ⌘ + Space, type `Terminal`, press Enter.

**Windows:** Press the Start button, type `PowerShell`, press Enter.

**Linux:** Ctrl + Alt + T usually does it.

You will see a window with some text and a blinking cursor. Type this and press Enter:

```bash
echo hello
```

It should print `hello`. That is you running a command. Nothing more mysterious than that is going
to happen for the rest of this module.

::: try If nothing happened
Check you pressed Enter, and that you typed `echo hello` and not `echo "hello` with a stray quote.
The terminal is picky about exact characters and completely unforgiving about typos — that is
normal and you will get used to it faster than you expect.
:::

## Step 2 — install Python

First check whether you already have it. Type:

```bash
python3 --version
```

If you see something like `Python 3.11.5`, you have it — skip to step 3. Any version starting with
`3.10` or higher is fine.

If you see an error, install it:

- **Mac and Windows:** go to [python.org/downloads](https://www.python.org/downloads/), download the
  installer, run it. **On Windows, tick the box that says "Add Python to PATH"** on the first screen
  — it is easy to miss and everything breaks without it.
- **Linux:** `sudo apt install python3` on Ubuntu or Debian.

Close the terminal, open a new one, and run `python3 --version` again. It should work now.

::: jargon PATH
A list your computer keeps of places to look for programs. When you type `python3`, your computer
searches that list to find it.

"Add Python to PATH" means "put Python somewhere I will look". If you skipped that box on Windows,
the fix is to re-run the installer and tick it.
:::

## Step 3 — your first program

Make a folder to work in. In the terminal:

```bash
mkdir agents-course
cd agents-course
```

`mkdir` makes a directory (a folder). `cd` means "change directory" — go into it. You are now
working inside that folder.

Now create a file called `hello.py`. Use any text editor: TextEdit, Notepad, or better, install
[VS Code](https://code.visualstudio.com/), which is free and made for this. Put this in the file and
save it **in the `agents-course` folder** you just made:

```python title=hello.py
print("Hello. I am a program.")
```

Back in the terminal, run it:

```bash
python3 hello.py
```

You should see:

```
Hello. I am a program.
```

**You have written and run a program.** That is not a participation trophy — the loop you just
completed (edit the file, run it, look at the output) is the loop you will be in for the rest of
this course and, if you carry on, the rest of your programming life.

::: jargon print()
An instruction that displays something on screen. `print("hello")` shows `hello`.

The round brackets hold what you want printed. The quote marks say "this is text, not an
instruction". Both matter, and leaving one out is the most common beginner error there is.
:::

## Step 4 — variables

A variable is a name for a piece of information, so you can refer to it later.

```python title=greeting.py
name = "Ada"
print(name)
```

Run it and you get `Ada`.

Read the first line as: *"let the name `name` refer to the text `Ada`"*. The `=` here does **not**
mean "equals" in the mathematical sense. It means "put this thing under this name". This trips
people up for about a day and then never again.

Now something more useful:

```python title=greeting.py
name = "Ada"
greeting = "Hello, " + name + ". Welcome."
print(greeting)
```

That prints `Hello, Ada. Welcome.` The `+` joins pieces of text together. Change `"Ada"` to your own
name, save, and run it again. **Actually do this** — changing a program and seeing the output change
is the moment this stops being abstract.

### The kinds of information you will use

Python distinguishes between a few types of thing, and mixing them up causes a lot of early errors:

| Type | What it is | Examples |
|---|---|---|
| **string** | Text. Always in quote marks. | `"hello"`, `"Ada"`, `"42"` |
| **integer** | A whole number. No quotes. | `42`, `0`, `-7` |
| **float** | A number with a decimal point. | `3.14`, `0.5` |
| **boolean** | True or false. Capital letter, no quotes. | `True`, `False` |

The one that catches everyone: `"42"` and `42` are different things. The first is text that happens
to look like a number; the second is a number you can do arithmetic with.

```python
print(2 + 2)         # 4        — arithmetic on numbers
print("2" + "2")     # 22       — joining two pieces of text
```

Neither is wrong. They are different operations, and Python did exactly what you asked.

::: jargon Comment
Anything after a `#` is ignored by the computer. It is a note for humans reading the code.

```python
# This line does nothing at all
print("This line runs")   # ...and this note is ignored too
```

Good code is full of them. You will thank yourself in a month.
:::

## Step 5 — reading errors

You will see errors constantly. Everyone does, at every level of experience. An error is not you
failing — it is the computer telling you precisely what confused it, which is enormously more useful
than it silently doing the wrong thing.

Errors are read **bottom-up**. The last line is what went wrong; the lines above say where.

Here are the three you will actually hit this week.

### SyntaxError

```
  File "hello.py", line 1
    print("Hello
          ^
SyntaxError: unterminated string literal
```

**Means:** you broke a rule of the language — usually a missing quote mark or bracket.
**Look at:** the line number given, and the one before it. Count your quotes and brackets.

### NameError

```
NameError: name 'nmae' is not defined
```

**Means:** you used a name Python has never seen. Almost always a typo, or using a variable before
creating it.
**Look at:** the spelling. `nmae` versus `name`.

### FileNotFoundError, or "can't open file"

```
python3: can't open file 'hello.py': [Errno 2] No such file or directory
```

**Means:** you are not in the folder where your file lives.
**Fix:** run `ls` (Mac/Linux) or `dir` (Windows) to see what is in the current folder. If `hello.py`
is not listed, `cd` into the right folder.

::: warn The most valuable habit you can build today
When you hit an error, read it. Actually read it. The instinct is to feel a flash of alarm and start
randomly changing things — everyone has it, and it costs hours.

The error usually tells you the file, the line, and the problem. Nine times in ten the fix is
sitting in the message.
:::

::: deeper What "python3" is actually doing
When you type `python3 hello.py`, you are running a program called `python3` and handing it your
file. It reads your file top to bottom and carries out each instruction in order.

Python is an *interpreted* language: it reads and executes as it goes, rather than being converted
into machine instructions ahead of time. That is why you see errors when execution reaches the bad
line, rather than before anything runs at all.

You do not need this to continue. It is here because "what is actually happening when I press
Enter" is a reasonable question, and the answer is not mysterious.
:::

## What you now know

- A terminal takes typed commands. `mkdir`, `cd`, `ls`/`dir`, `python3`.
- A program is instructions in a file, run top to bottom.
- `print()` displays things.
- A **variable** is a name for a piece of information; `=` means "put this under this name".
- Text, whole numbers, decimals and true/false are different types, and `"42"` is not `42`.
- Errors are read bottom-up and usually tell you the fix.
